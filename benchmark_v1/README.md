Benchmark v1: Difficulty-Controlled Structural Regime Family

This folder contains the frozen benchmark definition for the k-wallet RL project.

What this benchmark is

This benchmark consists of four synthetic transaction regimes that are:

structurally distinct
operationally comparable in difficulty

The four regimes are:

SL: smooth + light-tail
SH: smooth + heavy-tail
BL: bursty + light-tail
BH: bursty + heavy-tail

These regimes were generated by a unified transaction generator rather than manually creating four unrelated datasets.

Why this benchmark matters

The goal is not just to compare policies on arbitrary environments.

Instead, this benchmark is designed so that:

regime structure is clearly different
regime difficulty is approximately controlled

This makes it suitable for downstream experiments comparing:

specialist policies
generalist policies

without the results being dominated only by trivial difficulty differences.

Structural validation

The regime family was validated using structure-related statistics.

Time-structure indicators
state_avg_burst_length
state_burst_fraction

These distinguish smooth regimes from bursty regimes.

Tail-structure indicators
p95 / mean
p99 / mean

These distinguish light-tail regimes from heavy-tail regimes.

As a result:

SL and SH are smooth
BL and BH are bursty
SL and BL are light-tail
SH and BH are heavy-tail
Difficulty validation

Operational difficulty was estimated using two rule-based baselines:

FWF
FA

For baseline b and regime r, the difficulty proxy is defined as:

d(b,r) = 0.6 * (1 - ValAcc) + 0.4 * DropRate

where:

ValAcc = value acceptance ratio
DropRate = dropped transaction ratio

The final difficulty score for each regime is:

AvgDifficulty(r) = (d(FWF,r) + d(FA,r)) / 2

Average difficulty results
SL: 0.0450
SH: 0.0454
BL: 0.0403
BH: 0.0411

The maximum gap is about 0.0051, which is small enough for this project’s downstream controlled comparison.

Frozen benchmark policy

This benchmark is now treated as frozen benchmark v1.

That means the following should no longer be changed during main experiments:

regime generator parameters
global benchmark settings
regime order
difficulty proxy definition
baseline validation tables

If future changes are needed, create a new version such as:

benchmark_v2

Do not overwrite benchmark_v1.

Recommended downstream use

Use this benchmark for:

specialist training
train one policy per regime
generalist training
train one mixed policy across all regimes
cross-regime evaluation
evaluate specialist and generalist policies on all four regimes
generalist-vs-specialist comparison
compare performance, transfer behavior, and whether specialization is worth maintaining
